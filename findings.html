云端部署核实记录（S5，2026-11-04）

对象是腾讯云开发 CloudBase（本项目 PRD 结论 13／16 选的云端形态载体）。这份文档只干一件事： 把"云端能不能做、该不该做"从口头判断变成有原句的判断，并把没核实的地方明确留白。

0. 方法与边界（先说证据是什么级别）

  • 时间：2026-11-04。手段：官方文档站 docs.cloudbase.net 与 cloud.tencent.com 的文档页抓取，未开通环境、未部署、未调用任何云端接口。
  • 所以这份文档没有一条是"我跑出来的"，全部是"官方这么写的"。它足以支撑"要不要做"的决策，不足以支撑"性能如何"的结论。
  • 引号里的原句由网页抓取工具从页面正文取出，没有逐字与渲染页人工比对（个别长句中间有省略号，我按取到的样子保留）。要引用给别人，请点开 URL 自己复核一遍。
  • URL 全部是核实当天实际打开的页面，不是猜的、不是拼的。

1. 五条已核实事实（各配官方原句与 URL）

F1｜默认域名强制一个"访问提示中间页"，访客必须点击才能进入业务页

"用户通过浏览器直接访问的请求…将会展示'访问提示中间页'…访客需在阅读风险提示后，点击「确定访问」方可进入实际业务页面。"
"原有的'默认域名有效期续期'机制已正式下线。不再需要频繁进行手动续期，但「访问提示中间页」将作为一项软性安全提醒长期存在。"

来源：默认域名访问限制及中间页、HTTP 网关概述·默认域名 它决定什么：A6 的验收是"CloudBase 链接可访问，带口令保护"。默认域名下，链接打开的第一屏不是我的界面，是一道要人点的风险提示。

F2｜移除中间页的唯一合规途径是自定义域名，而自定义域名必须完成 ICP 备案

"自定义域名必须完成 ICP 备案…移除中间页的唯一合规途径是配置并使用自定义域名。"
"生产环境强烈建议绑定已完成备案的自定义域名，以获得完整的服务能力和稳定性保障。"

来源：默认域名访问限制及中间页、HTTP 网关概述、自定义域名 它决定什么：这一条把"云端演示"的成本从"部署脚本"抬到"备案流程"。备案是周级外部流程，不在一周项目预算里。

F3｜默认域名官方定位为"仅适用于开发测试阶段"，且有访问频率限制与停访问的风控权

"但基于安全合规要求，默认域名仅适用于开发测试阶段，存在以下限制：访问频率限制／部分高级功能不可用／可能存在稳定性风险"
"平台对默认域名访问量进行实时监控，若检测到访问量异常波动，平台保留采取禁止访问等风控措施的权利"

来源：HTTP 网关概述、默认域名访问限制及中间页 它决定什么：就算接受中间页，一个被投屏、被多人点开的演示链接正好落在"访问量异常波动"这一类风险里。

F4｜云函数超时有官方上限句"上限为 60s"，延长到 900s 属于计费能力项

"建议在云控制台调整为需要的超时时间（上限为 60s），在云函数内使用 callback() 返回成功，客户端不等待执行结果。"
"允许用户根据业务需求自定义云函数的运行时间上限和内存分配量，突破默认资源限制…支持将运行时间最多延长至 900s，内存扩展至数 GB。"

来源：云函数常见问题·性能相关、云开发 CloudBase 计费能力项说明 它决定什么：结论 16（云端只读、上传区禁用）依赖的"60 秒"现在有原句了；但免费体验版到底能设到哪一档没核实（见 U1），所以这条支撑的是方向，不是精确预算。

F5｜内置对话模型免 API Key 调用，免费额度用尽后自动从套餐资源点抵扣

"调用时使用 cloudbase provider（ai.createModel("cloudbase")），免费额度用尽后会自动从套餐资源点抵扣，无需配置 API Key。"
"切换后还可直接使用 deepseek-v4-flash、glm-5.2、kimi-k2.6、minimax-m3 等更多模型。"

来源：AI 常见问题 FAQ 它决定什么：云端形态不需要自带模型 Key 就能出答案，这是"可行路径"里最实的一条。列出的都是对话模型，嵌入模型是否内置没找到原句（见 U3）。

附：两条支撑数字（同样有原句，不单独算"事实"）

"免费体验版：0 元/月（3,000 点）"；"Q: 超出套餐配额后怎么收费？ A: 超限部分按 1:1 的比例扣费（即 1000 点 = 1 元）。" —— 资源点计费 FAQ 这条把 PRD 里"免费环境每月 3000 资源点"从记忆升级成有原句。注意它只回答计费，不回答服务行为（见 U5）。
"上传方式说明：默认使用 cos，可指定 zip（限制 1.5MB）或 image（镜像部署）。" —— 云函数 API 参考 这条是"函数内置小索引"能成立的尺寸依据（见 P1）。

3. 如果将来要做：验证过的可行路径

"验证过"指每一步都挂着一条官方原句或本仓实测原料，不是"我估计可以"。

P1｜函数内置 0.9MB 索引，检索在函数里现算余弦（不依赖云端向量库）

  • 原料（本仓实测）：索引 216 条 × 维度 1024（docs/model-selection.md 真实调用量出来的），float32 存 → 216×1024×4 ＝ 884,736 字节 ≈ 0.88 MB（float16 可再减半，本仓未实测）。
  • 尺寸依据（官方原句）：代码包 zip 直传"限制 1.5MB"（见 §1 末尾附条）。0.88 MB 装得下，还有余量放代码。
  • 为什么这条路绕开了 U6：不需要 pgvector，也不需要 chroma——现算余弦只需要一个数组。
  • 待验证：函数内存/CPU 档位下的实际耗时，以及 216×1024 次乘加在免费档会不会顶到超时（U1）。这条我只能说"没有依赖挡住它"，不能说"实测很快"。

P2｜对话模型用内置免 Key 的那条

  • 官方原句：ai.createModel("cloudbase")、"无需配置 API Key"（F5）。
  • 落到本仓架构是一个 plugins/llms/ 新文件 ＋ 一行配置，core/ 不动——这正是 6 条"主程序零改动"提交走过的路。
  • 代价：换模型＝换答案层行为，现行 v8 那套 27 题数字全部作废，云端那一行必须另起一行、另标口径，不能拿来替换本地成绩。

P3｜嵌入模型走第三方 ＋ Key（因为内置嵌入未核实）

  • U3 没核实，所以不能把"云端也有内置 embedding"写进设计。可行路径是 embedders 再加一个 openai-compatible 型插件，Key 从环境变量读、不入库。
  • 硬约束（本仓实测）：dim=1024 是配置与索引的契约——换嵌入提供方很可能换维度，换维度＝索引必须重建，而 P1 的 0.88MB 索引和 min_score=0.5 这条阈值都是当前嵌入模型的产物。云端索引必须由与本地同一模型生成，否则分数不可比，拒答判据直接失真。
  • 结论：云端形态真正要动的不是"部署脚本"，是嵌入提供方 ＋ 阈值重标定，这就是行 E／行 M 那一族的预算，不是半天能收口的。

4. 为什么本版不做（已核实的主动不做，不是没来得及）

  1. 默认域名强制中间页，访客必须点「确定访问」才能进业务页（F1 原句）。这个项目的真实读者是"面试官的 5 分钟"，第一屏是一道要人确认的风险提示——演示动线被平台打断，而这还没算上口令那一层。
  2. 移除中间页的唯一合规途径是绑定已完成 ICP 备案的自定义域名（F2 原句）。备案是周级外部流程，不在一周预算内；我也不打算为了一个演示链接去借一个域名。
  3. 再叠加 P3 那条本仓契约约束（换嵌入＝换维度＝重建索引＝重标阈值），云端形态的成本远高于它给这个作品集带来的加分。

所以：A5/A6 保持"接口预留已验证、实现待补"，云端不写进任何"已实现"的说法（结论 23 已经为这条打过一次假，不打算打第二次）。
