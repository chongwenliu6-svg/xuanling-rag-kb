预计算检索页README 实验表云端核实

声明一（实时性）：本页展示的是预计算的检索结果，不是实时系统。输入不在题集内的问题不会得到答案——这里没有任何模型、没有网络请求、没有可查询的索引。

声明二（口径）：本页每个数字都跟着口径版本（R2b→R2b2→R2c2→R2d 时间线），口径与 `README.md` §4 同源；跨口径的两行之间不做差值，页面自己不算任何指标。

实验记录

按 PRD 第 3 节「实验纪律」与「评测集口径」维护：每次只改一个变量，复用冻结的 27 题与同一份语料快照，

变差和不好看的数字一律留在表里，不许删行、不许修饰。

跑分命令（尺子本身，不参与被测量的东西）：

python -m eval.run --stage retrieve        # 16 秒，不动对话模型：只算 Recall@5 与排名分布
python -m eval.run --stage full            # 104 秒，走真实管线：27 题一次跑完，14 项计数型指标全自动产出（9 正 + 5 负）

出厂默认现在是 prompts.active = corpus_framed + policies.active = cited_only，即 baseline-current-v8（行 P2 经 R2d 转正） （行 P1 转正，结论 22），并由 tests/test_assembly.py 的一条断言锁住；legacy_v1 判据仍作为可选插件保留， 复现历史行时显式选中它。采样默认固定（temperature = 0.0 + seed = 20261102），云端提供方配置段同口径。 集外抽查用 --queries eval/queries.probe.jsonl（3 题，只查形状，冻结的分母只管正式集）。

口径（PRD 第 3 节 2026-11-02 正名后的名字；JSON 键名保持不变，否则历史产物读不了）

列按层归属，一列只属于一层——换某层的插件时，别层的列必须一动不动，否则就是在同时改两件事。

列（现名）层JSON 键原名

  • Recall@5：gold 片段是否落在不过阈值的原始 top5 里。衡量检索本身，与 min_score 无关。
  • 放行含gold率（检索层）：检索放行的证据里有没有 gold 文件（不要求是那片）。22 题里有 3 题文件对、片段没进前 5。换呈现插件时这一列不许动——R2c 之前它数的是展示列表、会跟着动，已修。
  • 实质作答率：模型真的给了内容，而不是回一句「资料中没有」。用户唯一能感知的指标。
  • 模型真引用gold率（呈现层）：未被管线拒答的题里，展示给用户的出处列表含 gold 文件的占比。legacy 判据把证据全列出来时它退化成「检索放行了 gold 文件」的影子，从来没量过模型有没有老实引用（题 14 是活证据）。
  • 过度拒答率：gold 片段已进上下文、模型仍答「资料中没有」的占比。分母只数 gold 被放行的 11 题——管线已拒答的题不算，否则同一道失败会被假阴性列和这列重复计一次（tests/test_eval_run_metrics.py::test_管线拒答单独算假阴性 守的就是这条）。
  • 污染率两个口径并报：文件名 ≠ 标注 gold 文件的条目占比（分母是条目数，不是题数）。
  • 全证据口径：分母＝放行给模型的全部证据（released），与 v2 那列同一定义，历史行可比；
  • 展示口径：分母＝用户真正看到的出处列表（citations）。呈现层修复只收窄列表，所以全证据口径不动、展示口径下降，两列之差就是修复量。
  • ⚠ PRD 早期写的「宽松判定＝同主题文件也算相关」尚未实现：它要给每题标注可接受文件集合，属于改题集，冻结口径下要走一次独立尺子修订。现有两列都不许被叫成那个意思。
  • ⚠ 0.709（全证据口径）是算术上界（列满 5 条必然污染 4 条），对外不许表述成「71% 的答案是错的」。
  • 无有效引用率：放行过证据、模型却没给出任何有效编号（自打编号 ∩ 真实命中为空）的题数占比。这类题的出处列表为空，必须看得见而不是静默。legacy 判据下这一列恒为 0（构造性，不是实测），换 cited_only 之后才是真测出来的。
  • 负样本正确拒答率：库里本来没有答案的 5 题里，最终没给实质答案的占比，并拆分管线层拦下几个、模型自己拒了几个。
